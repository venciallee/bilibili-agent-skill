# bili-chapters

```bash
bili chapters transcript.srt --target 6
```

工具是这个仓库的 `bili` 命令（Go 写的，零依赖，只读本地文件，不登录、不调 B站接口）。没装的话：

```bash
go install github.com/venciallee/bilibili-agent-skill/cmd/bili@latest
```

装不了 Go 时，按下面的规则手工检查，并在输出里写明“这次没有跑工具”。

## 规则，不是建议

不满足这些，官方分段章节就设置不了。以 2026-11 为准，平台改了就用 `--min-video`、`--max` 覆盖：

- 稿件**已过审**、时长**超过 5 分钟**、**不是互动视频**
- **2 到 10 段**，每段**至少 5 秒**，不能重叠
- 每段标题**少于 16 个汉字（或 32 个英文字母）**

设置位置在电脑网页端：创作中心 → 稿件管理 → 对应稿件的“…” → 个性化配置 → 分段章节。只能在过审之后设置，所以章节是**发布后的第一件事**，提前写好。

5 分钟以内的视频用不了官方章节。工具会同时输出一份时间戳版，贴进置顶评论，时间会变成可点击的跳转。

## 每一行都要重命名

`bili chapters` 找**边界**找得不错——它看你真实停顿的长短，以及停顿前后用词变了多少。但它给的标题是话题词，是草稿。一个叫“上限·maxlimit”的章节是占位符。按用户的口吻，把每一行改写成这一段的承诺，3 到 8 个字。

章节也是留存诊断：一段如果五个字说不出它在讲什么，它要么是两段，要么是水。

## 闸门

这里什么都不会发布。skill 只负责写，投稿由你来点。每次输出都以一个可以直接复制的块结尾，最后一句永远是：**就这么发，还是改？**
