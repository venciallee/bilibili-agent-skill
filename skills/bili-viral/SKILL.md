# bili-viral

原始播放量排的是账号大小，不是点子。这里按**每个 UP 主自己中位数的倍数**排，这才是关于视频本身的问题。

```bash
bili viral collected.json --min 2.0
```

工具是这个仓库的 `bili` 命令（Go 写的，零依赖，只读本地文件，不登录、不调 B站接口）。没装的话：

```bash
go install github.com/venciallee/bilibili-agent-skill/cmd/bili@latest
```

装不了 Go 时，按下面的规则手工检查，并在输出里写明“这次没有跑工具”。

## 收集数据

每个 UP 主至少要 **4 个视频**，否则中位数没有意义，工具会跳过并说明。

- `yt-dlp -j --skip-download --playlist-end 30 "https://space.bilibili.com/<UID>/video" > collected.jsonl` 逐行输出每个视频的 JSON（标题、播放、点赞、评论数）。B站有风控，被拦（412 / -352）就停下等，**不要**换着法子硬抓。
- 投币、收藏、弹幕数在视频页上公开可见，想知道“赢在哪”就补进去。手工整理也行：

```json
[{"up":"...","title":"...","view":412000,"like":31000,"coin":18000,"favorite":26000,"danmaku":5200,"reply":2100,"bvid":"BV...","pubdate":1760000000}]
```

找候选的地方：分区热门、每周必看、排行榜、搜索结果。

**只读，不抓。** 不登录，不用用户的 cookie 或账号，不调 B站的非公开接口，不做请求签名。

## 读结果

- **倍数**是信号。发布不到 7 天的视频会标出来——它还在涨，倍数偏低。
- **赢在哪**：互动率相对这个 UP 主自己中位数的倍数。收藏型＝观众存起来以后用（教程、清单）；投币型＝硬币稀缺，这是认可；讨论型＝弹幕和评论多，引发了争论或者梗；点赞型＝喜欢，但没留下来。
- **公式**是对标题字面的判断（对照 [21 个公式](../bili-script/hooks.json)），不是对它为什么火的解释。给用户看的时候要这么说。

## 交回什么

前五名，带倍数、公式和赢在哪；它们共有的**一个**结构特征。然后是更难的那句话：其中哪一个是用户这周就能做的——用他的口吻、用他手上已有的东西。
