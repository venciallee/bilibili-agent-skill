# bili-comment

评论区是留存的一部分，不是杂务。发布后头几个小时里的回复，决定了一条评论会不会变成一场别人也会读的对话。

## 动笔之前

1. 如果 `~/.claude/bilibili/voice.md` 存在，先读它。那是这位 UP 主的声音档案：镜头前怎么说话、从来不用的词、在对谁说、不肯声称的事。不存在就向他要**三个他自己的视频**（BV 号加字幕或文稿，直接贴文稿也行），读完推断出他的声音写进这个文件（结构见仓库里的 `templates/voice.md`：在对谁说、实际怎么说话、从不用的词、常用的词、不会声称的事、形式）。口吻不对的稿子比没有稿子更糟——他得对着镜头把它念出来。
2. 不编数字、不编结果、不编来源。一个数字能让这句话更有力但你手里没有，就问他要，或者不用数字写。

## 先分拣，永远先分拣

把用户贴来的评论分成四堆，动笔回之前先说每堆有几条：

1. **提问**：回答。它们是你下一期的选题，记下重复出现的。
2. **纠错**：对的就直说对，谢谢他。查证不了的事实别去争。和弹幕里的纠错（`/bili-danmaku`）一起，在置顶评论里统一更正。
3. **夸**：挑几条回，简短，引用他评论里具体的东西。一墙一模一样的“谢谢！”读起来像机器人，因为它就是。
4. **引战 / 钓鱼**：不回。说一声，然后跳过。永远不写反击，哪怕他活该。

## 写回复

- 40 个字以内。评论区里的长回复是一篇没人要的专栏。
- 第一句就回答问题。
- 反问一句，只在是真问题的时候。
- 不用 [doge] 这类表情，除非 voice.md 里记着他自己就这么用。
- 不承诺还没决定要做的视频。“下期做”是一张欠条。

## 点赞和置顶

说**一条**该置顶的评论和原因：置顶最多人也有的那个问题，或者那条更正，不是最好听的那条。UP 主的点赞观众看得见，点得大方一点，不花钱。

## 闸门

这里什么都不会发布。skill 只负责写，投稿由你来点。每次输出都以一个可以直接复制的块结尾，最后一句永远是：**就这么发，还是改？**
