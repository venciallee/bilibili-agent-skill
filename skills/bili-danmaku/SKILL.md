# bili-danmaku

弹幕是别的平台给不了的反馈：观众在**那一秒**打出他对视频的看法。留存曲线告诉你人在哪里走了，弹幕告诉你他们走之前在想什么。

```bash
bili danmaku danmaku.xml --transcript transcript.srt --retention retention.csv
```

工具是这个仓库的 `bili` 命令（Go 写的，零依赖，只读本地文件，不登录、不调 B站接口）。没装的话：

```bash
go install github.com/venciallee/bilibili-agent-skill/cmd/bili@latest
```

装不了 Go 时，按下面的规则手工检查，并在输出里写明“这次没有跑工具”。

## 拿到弹幕

- `yt-dlp --skip-download --write-subs --sub-langs danmaku "https://www.bilibili.com/video/BV..."` 会把弹幕存成 `.danmaku.xml`。多 P 视频在链接后加 `?p=N`，每个分 P 的弹幕是分开的。
- 也接受 `[{"time": 秒, "text": "..."}]` 这样的 JSON。
- 只读公开数据：不登录、不用用户的 cookie、不批量抓。分析别人的视频用于学习可以，别把别人的弹幕原样搬运出去。

## 五个信号

- **空降**：“空降 2:33”是一个观众在告诉别人跳到 2:33。工具把每条空降的**发送时间**和**目标时间**配成对，成组出现时，中间那一段就是观众集体判定可以跳过的。这是最直接的信号，因为观众把原因写出来了。
- **疑惑**：“？”“没懂”“啥意思”扎堆的地方，就是该补一句解释、加一个画面的地方。
- **高峰**：反应远高于这条视频自己均值的格子。看高峰里**是什么**：笑多是梗，是切片候选（交给 `/bili-clip`）；高能多是名场面；问号多就回到上一条。
- **纠错**：“应该是…”“口误”。对的就在置顶评论里更正（`/bili-comment`），比重新投稿便宜得多。
- **沉默区**：很久没人开口。沉默不一定坏——也可能大家在认真看；但它和留存曲线上的滑坡重叠时，就是观众在悄悄离开。

## 偏差，报告会直接写出来

- XML 只有弹幕池里**最新的一批**，上限写在 `maxlimit` 里。顶到上限，早期弹幕已被挤掉，分布偏向最近的观众。
- 开头天然偏高：人最多，还有一堆“来了”“前排”；结尾有“三连”“下次一定”。这两类和空降不计入反应密度。
- 给了 `--retention` 会按当时还在看的观众比例归一化，高峰才是真的高峰，不是人多。
- 分类按字面规则判（“哈哈”算笑、“？”算疑惑），说的是观众打了什么，不是视频为什么好或不好。

## 交回什么

**最能直接动手的那一条**：通常是空降区间（剪掉，或者把答案前置）或者疑惑点（重写那一段），带上时间码和那里在说的原话。然后是能切片的高峰和需要回应的纠错。不要把整份报告复述一遍。
