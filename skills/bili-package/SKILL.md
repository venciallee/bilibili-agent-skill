# bili-package

标题和封面是**同一个单位**。分开写是大多数包装失败的原因：封面把标题又说一遍，一半的点击面积在说重复的话。

```bash
bili title --title "..." --cover "封面大字"
bili title titles.txt --cover "封面大字"     # 每行一个标题，排序
```

工具是这个仓库的 `bili` 命令（Go 写的，零依赖，只读本地文件，不登录、不调 B站接口）。没装的话：

```bash
go install github.com/venciallee/bilibili-agent-skill/cmd/bili@latest
```

装不了 Go 时，按下面的规则手工检查，并在输出里写明“这次没有跑工具”。

## 动笔之前

1. 如果 `~/.claude/bilibili/voice.md` 存在，先读它。那是这位 UP 主的声音档案：镜头前怎么说话、从来不用的词、在对谁说、不肯声称的事。不存在就向他要**三个他自己的视频**（BV 号加字幕或文稿，直接贴文稿也行），读完推断出他的声音写进这个文件（结构见仓库里的 `templates/voice.md`：在对谁说、实际怎么说话、从不用的词、常用的词、不会声称的事、形式）。口吻不对的稿子比没有稿子更糟——他得对着镜头把它念出来。
2. 不编数字、不编结果、不编来源。一个数字能让这句话更有力但你手里没有，就问他要，或者不用数字写。

## 工具检查的规则，和为什么

- **80 个字符**是投稿页的硬上限，超了发不出去。
- **约 24 字宽**是手机首页双列卡片两行标题能显示的量，再长就折叠成“…”。英文和数字按半个字算。机型和字号不同会有出入，用 `--feed` 改。
- **前 12 个字**才是划屏的人真正读到的，主体必须在里面。开头一个长长的【4K·中字·无剪辑】会把这 12 个字吃掉。
- **封面不能复述标题。** 不同的字，同一个承诺。
- **封面大字最多两行、每行六个字左右**（约 12 字）。在信息流卡片的尺寸上，再多就是一团灰。
- **数字、名字、日期**胜过你能找到的任何形容词。
- **绝对化用语**（全网最、史上最、第一）：商单稿件里是广告法的禁区，非商单也最容易招来弹幕当场挑刺。把范围说出来：“我测过的五款里最快的”。
- **“！！”“？？？”连用**读起来像在喊。

## 封面的物理规则

封面按 **4:3** 上传（1200×900）。手机首页用 4:3，别的地方会裁成 16:10 或 16:9。所以**字和脸都放在画面中间的 16:9 横带里**——上下各约八分之一是会被裁掉的“出血”。封面上的东西要能在视频里找到，封面党会在弹幕和评论区被当场拆穿。

## 写十个，留两个

生成十个标题，全部过 `bili title`，把前三名连同分数和各自的具体问题给用户看。为胜出的那个写封面 brief：表情、构图、那几个大字、背景要怎么在卡片尺寸下保持对比度，以及 16:9 安全区里放什么。

## 闸门

这里什么都不会发布。skill 只负责写，投稿由你来点。每次输出都以一个可以直接复制的块结尾，最后一句永远是：**就这么发，还是改？**
