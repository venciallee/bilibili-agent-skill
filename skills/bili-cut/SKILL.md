# bili-cut

从带时间码的字幕生成一份粗剪决策表。它打印要剪的地方，剪由你来剪。

```bash
bili cut transcript.srt                    # srt / vtt / whisper json / B站 BCC 字幕 json
bili cut transcript.srt --floor 0.35 --json
```

工具是这个仓库的 `bili` 命令（Go 写的，零依赖，只读本地文件，不登录、不调 B站接口）。没装的话：

```bash
go install github.com/venciallee/bilibili-agent-skill/cmd/bili@latest
```

装不了 Go 时，按下面的规则手工检查，并在输出里写明“这次没有跑工具”。

还没有字幕就先要一份，或者先生成一份——剪映 / 必剪的“识别字幕”导出 SRT、`whisper` / `faster-whisper`、B站 AI 字幕的 BCC json 都可以。**不要猜时间。**

## 它找什么

- **停顿**：超过阈值的空白，**从中间剪**，两边各留半个阈值的气口。贴着话头话尾剪，紧过的口播听起来像喘不上气。
- **口癖**：整行只有“嗯”“啊”“那个”“就是”“然后”的字幕。
- **重说**：同一句话开头说了两遍，或者第一遍说到一半断了，剪掉前一遍。对比的是上一句**真正有内容的话**，不是字面上的上一行——大多数重说中间都夹着一个“嗯”。

## 它不做什么

不碰素材，对你的 B-roll 没有意见。报告里的“短了 40%”是**说话部分**短了 40%；视频里有长段无声演示的话，这个数就是错的，先对着素材核一遍再信底部的时长。

剪映不能直接导入这份表。按时间码在时间线上剪；需要的话，把这份表整理成用户所用剪辑软件的逐步操作清单。

## 闸门

这里什么都不会发布。skill 只负责写，投稿由你来点。每次输出都以一个可以直接复制的块结尾，最后一句永远是：**就这么发，还是改？**
