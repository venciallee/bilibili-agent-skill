# bili-script

一个想法，变成一份有人看得完的口播稿。

```bash
bili hook hooks.txt              # 每行一个开头，排序打分
bili hook --hook "一句话"         # 单独打一句
bili formulas                    # 列出 21 个公式
```

工具是这个仓库的 `bili` 命令（Go 写的，零依赖，只读本地文件，不登录、不调 B站接口）。没装的话：

```bash
go install github.com/venciallee/bilibili-agent-skill/cmd/bili@latest
```

装不了 Go 时，按下面的规则手工检查，并在输出里写明“这次没有跑工具”。

不要凭感觉判断钩子，跑工具。

## 动笔之前

1. 如果 `~/.claude/bilibili/voice.md` 存在，先读它。那是这位 UP 主的声音档案：镜头前怎么说话、从来不用的词、在对谁说、不肯声称的事。不存在就向他要**三个他自己的视频**（BV 号加字幕或文稿，直接贴文稿也行），读完推断出他的声音写进这个文件（结构见仓库里的 `templates/voice.md`：在对谁说、实际怎么说话、从不用的词、常用的词、不会声称的事、形式）。口吻不对的稿子比没有稿子更糟——他得对着镜头把它念出来。
2. 不编数字、不编结果、不编来源。一个数字能让这句话更有力但你手里没有，就问他要，或者不用数字写。

## 结构

**前 15 秒就是全部工作。** 它要干三件事，少一件就漏人：兑现标题和封面许下的承诺；抛出一个观众合不上的问题；证明答案真的存在。

1. **钩子。** 照着 [21 个公式](hooks.json) 写**五个**，全部过一遍 `bili hook`，留前两名，连同分数一起给用户看。永远不要只交一个钩子。
2. **转折**（0:15–0:45）。一句话说清这期要做什么，然后马上开始做。没有片头，没有“大家好我是”，没有“先点个关注”——这些是开头流失最常见的原因，`bili hook` 会把它们当红线扣分。
3. **正文。** 一个节拍一个点。每个节拍都标 `[画面：…]`，写的是屏幕上**看得到**什么——只有一张脸、没东西可看的口播，就是播客。
   - 超过 5 分钟就按章节写：每一段能用不超过 15 个字说出它的承诺，这样 `/bili-chapters` 发布后能直接用。说不出来的段落，要么是两段，要么是水。
   - 留一到两个“弹幕位”：一个真实的问题、一个会让人想打字的瞬间。别写“弹幕扣 1”——那是在讨弹幕，不是在给理由。
4. **兑现。** 把钩子承诺的东西明确交出来，并说出你在交付：“这就是那段代码，链接在简介里。”
5. **结尾。** 一个请求，只有一个。要三连就只要三连，要评论就只问一个问题。

## 交回什么

- 分数最高的两个钩子，带完整打分面板
- 口播稿，按节拍分段，每个节拍都有 `[画面：…]`
- 时长估算：按 240 字/分钟算（快节奏知识区口播可按 280 算，以 voice.md 里记录的实测语速为准）
- 一行说明：胜出的钩子用了哪个公式，为什么适合这个选题

## 闸门

这里什么都不会发布。skill 只负责写，投稿由你来点。每次输出都以一个可以直接复制的块结尾，最后一句永远是：**就这么发，还是改？**
